# M1-169 tail64_nofinal TP1 screen

## Question

`admission64` preserves the final complete-block GDN state by splitting a
prefill at that boundary. M1-169 tested whether omitting unique final capture
points could remove that extra scheduler step without losing useful cache
coverage. The candidate policy was `tail64_nofinal`; `admission64` was the
control.

This was a development screen, not a production benchmark. It used the
four-layer real-weight diagnostic model on one BI100 GPU. It did not evaluate
the official 881-request workload, full-model quality, or TP4 behavior.

## Fixed setup

- source: `badcfe5ac946b9b4d7a73d62581a82e3275deefe`;
- runtime tree: `858c38f927db994a1c142c5af897074ef96a18a31e03f7215cd079fbadf7a339`;
- instance/GPU: `ssh-73ca29ba`, GPU 1;
- model: Qwen3.6-35B-A3B four-layer real-weight diagnostic checkpoint;
- TP=1, max model length 262144, chunk size 8192, max sequences 1;
- restore mode `hybrid64` and identical 18-request order for both arms;
- request lengths 4096, 7800, and 16000 tokens with cold, warm, and branch
  variants.

The command included `--num-gpu-blocks-override=552637`, but the old overlay
did not install `patch_worker_profile_override.py`. Therefore the run still
executed normal startup profiling. This does not invalidate the policy A/B:
both arms used the same runtime and startup path. It does mean the override
must not be credited with reducing this run's startup time.

## Result

All runner lifecycle gates passed: both arms, preflight, comparison, cleanup,
postflight, final preflight, and fatal scan returned zero. Both arms completed
all requests successfully.

| Metric | admission64 | tail64_nofinal | Candidate change |
| --- | ---: | ---: | ---: |
| Effective cache hit | 62.78% | 14.68% | -48.09 pp |
| Cached tokens | 105,072 | 24,576 | -76.61% |
| Cache TPS | 22,252.39 | 1,871.47 | -91.59% |
| Input TPS | 4,565.82 | 4,383.50 | -3.99% |
| Output TPS P10 | 67.554 | 67.551 | -0.004% |
| TTFT P90 | 2.969 s | 3.167 s | 6.69% slower |
| Diagnostic weighted proxy | 26,375.71 | 14,452.03 | -45.21% |

The mechanism is visible by request length. The candidate retained no warm
cache at 4096 or 7800 tokens, versus 12,240 and 23,376 cached tokens for the
control. At 16000 tokens it retained 24,576 warm tokens, versus 47,952 for the
control. Natural 8192-token scheduler boundaries alone do not represent the
short and non-aligned session prefixes in this matrix.

Cold/warm output hashes matched within each arm. Cross-service, cross-policy
output hashes matched for 16 of 18 requests. Cross-policy exactness was not a
hard gate for this diagnostic analysis, and the four-layer model was not a
semantic quality oracle. The two mismatches therefore remain a quality reason
not to promote the candidate, independently of its decisive performance loss.

## Harness findings

The run exposed three iteration-cost defects, all limited to development
tooling:

1. the port-release probe lacked `SO_REUSEADDR`, so TCP teardown was mistaken
   for an occupied listener and produced repeated tracebacks;
2. the lifecycle unit test waited for PID-file existence, not a complete PID,
   creating a flaky empty-file read;
3. `patch_worker_profile_override.py` was tested but absent from the actual
   `patch_ops.sh` runtime installation chain. Its guarded-block anchor had also
   drifted from the startup guard patch.

The corrected exact overlay at
`91178057d5a29e9d592a3f9e35281d3b1918f4b8` builds and verifies successfully.
Its runtime tree is
`93f65cce49f5455401ae35c97371b0e8dbf0f94e7ab23878d2e7c5991603e849`.
Runtime source inspection proves that an explicit diagnostic override returns
before the method's first `torch.cuda.empty_cache()`, while the normal
`profile_run()` path remains present. The formal YAML and `launch_service`
still do not set or expose this override.

## Decision

Reject `tail64_nofinal`. Do not run it on TP4, do not change the default
`admission64/hybrid64` policy, and do not modify `computility-run.yaml` or
`main` from this result.

The next cache optimization must preserve final session checkpoints. Removing
them trades away the dominant reusable prefixes. A future implementation may
capture a full-block state inside an existing GDN chunk, but it must first
prove state equivalence and avoid adding another scheduler step.

Structured, privacy-safe evidence is under
`docs/experiments/evidence/M1_169_TAIL64_NOFINAL_TP1_20260801`.
