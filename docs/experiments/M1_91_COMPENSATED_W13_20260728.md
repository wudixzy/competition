## Scope

M1-91 is one bounded, probe-only alternative for the rank-local Qwen3.6 MoE
W13 matvec. It does not modify the installed runtime, model code, request
semantics, `computility-run.yaml`, Dockerfile, default flags, `main`, or
repository visibility.

The production direct W13 probe previously measured relative L2 values of
approximately:

- seed `20260716`: `7.302e-6`;
- seed `20260727`: `2.452e-5`.

The second seed exceeds the project-wide `relative L2 <= 1e-5` custom-kernel
gate. M1-63 already rejected a four-part pairwise accumulation variant:
its fixed-seed and 500-step errors remained above the gate despite useful
microbenchmark speed. M1-88 tests a forward/reverse disagreement detector,
but a CPU-only screen showed that such a detector can miss rounding errors.

M1-91 therefore evaluates one materially different algorithm rather than
continuing a tile, threshold, or reduction-order scan.

## Candidate Algorithm

The fixed rank-local shape is:

```text
experts=256
top_k=8
hidden=2048
intermediate=128
W13 rows per expert=256
input/output dtype=FP16
accumulation dtype=FP32
```

Each warp owns one selected-expert output row. Each lane processes the same
64 scalar products as the production direct kernel, but uses Kahan
compensation:

```text
product = round_fp32(weight * input)
adjusted = round_fp32(product - correction)
next = round_fp32(sum + adjusted)
correction = round_fp32(round_fp32(next - sum) - adjusted)
sum = next
```

The warp tree then uses explicit round-to-nearest FP32 additions, followed by
one FP16 output conversion. The implementation deliberately uses
`__fmul_rn`, `__fadd_rn`, exact sign inversion for subtraction, and
`__float2half_rn`; it does not use fast-math or FMA accumulation. This keeps
the candidate within the explicit intrinsics already exercised by existing
CoreX extensions in this repository.

## Fixed Evidence Contract

The benchmark uses exactly:

- device `cuda:0`, after mapping one declared physical GPU;
- seeds `20260716,20260727`;
- fixture order `hidden -> router -> W13 -> sequence`;
- W13 random scale `0.02`;
- 500 sequence steps per seed;
- 30 warmups, 300 iterations, and 9 timing repeats;
- production direct W13 and `torch.nn.functional.linear` controls.

For each fixed seed it reports:

- vendor FP16 linear versus a CPU float64 dot rounded to FP16;
- production direct W13 versus vendor;
- compensated W13 versus vendor;
- compensated W13 versus the float64 diagnostic.

For each 500-step sequence it separately aggregates production direct and
compensated finite steps, exact steps, mismatches, max/mean absolute error,
relative L2, and maximum per-step relative L2. Raw tensors, weights, token
data, prompts, and model outputs are never written.

The benchmark hashes the exact candidate and direct `.so` files. The
qualifier independently rehashes both files and binds the SHA-256 of the
parsed benchmark bytes. The runner performs one additional binding check
before accepting the result.

## Qualification Gates

All gates are mandatory:

1. The exact shape, seed, step, timing, and fixture contracts are unchanged.
2. Candidate and direct extension SHA-256 identities are valid, distinct,
   and match the files supplied to the qualifier.
3. The candidate is finite for both fixed fixtures and all 1,000 sequence
   steps.
4. Candidate-versus-vendor fixed relative L2 is at most `1e-5` for each seed.
5. Candidate-versus-vendor sequence aggregate and maximum per-step relative
   L2 are each at most `1e-5` for each seed.
6. At least one production direct fixed or sequence metric exceeds `1e-5`.
   Otherwise the fixture did not reproduce the known numerical problem.
7. Candidate fixed speedup versus vendor is at least `1.5x`.
8. Candidate routed speedup versus vendor is at least `1.25x`.
9. All timing trials and their recomputed quantiles are finite, positive,
   and internally consistent.

A qualified result only establishes a single-GPU component result. It does
not authorize production integration, a default change, a YAML change, a
`main` merge, or any model-quality claim.

If any numerical or speed gate fails, M1-91 is rejected as designed. Do not
scan compensation variants, tiles, thresholds, or tolerances. A passing
result permits one separately gated production-integration experiment, which
must still pass next-token, complete-request, tool/reasoning/multimodal,
cold/warm, long-context, TP4 stability, and end-to-end performance gates.

## Non-qualifying CPU Screen

The local machine has neither Torch nor NumPy. A committed standard-library
screen therefore emulates IEEE FP16 storage, FP32 round-after-each-operation,
the fixed 32-lane assignment, and the same FP32 warp tree. With seed
`20260727`, 16 steps, and 256 rows per step, it observed:

| method | aggregate relative L2 | max-step relative L2 | mismatched FP16 rows |
|---|---:|---:|---:|
| direct | `4.3141e-6` | `1.66595e-5` | 6 / 4096 |
| compensated | `1.07640e-6` | `4.04053e-6` | 4 / 4096 |

This screen makes the fixed candidate worth testing because it reproduces a
direct max-step failure and moves the compensated result below `1e-5`.
However, its reference is `math.fsum` rounded to FP16, not CoreX vendor
`F.linear`; its random stream is CPython rather than CoreX Torch. The report
sets `qualified=false` and cannot satisfy any GPU, model, or promotion gate.
Evidence is in
`docs/experiments/evidence/M1_91_COMPENSATED_W13_CPU_SCREEN_20260728.json`.

## Lifecycle Contract

The runner:

- refuses a dirty source tree or an output path outside private `/tmp`;
- verifies the immutable bare-host runtime and production direct extension;
- records source revision, branch, runtime identity, GPU, and artifact hashes;
- runs build and benchmark in separately attested sessions bound by
  PID/PGID/SID, `/proc` starttime, and a random session token;
- only signals those recorded process groups;
- sends `SIGTERM`, waits 60 seconds, sends `SIGKILL` only to survivors, then
  waits/reaps;
- validates the recorded-session cleanup report;
- runs before/after per-GPU compute preflight and GPU/process postflight;
- recursively scans stdout/stderr/logs and all return-code/timeout files for
  CUDA/CoreX fatal errors, OOM, Gloo/NCCL failures, worker loss, timeout, and
  state corruption;
- invalidates the experiment if the source changes while it is running.

Example after an immutable overlay is installed:

```bash
BI100_RUNTIME_SITE_PACKAGES=/tmp/<overlay>/site-packages \
  scripts/run_m1_91_compensated_w13.sh \
  <physical-gpu-index> \
  <instance-label> \
  /tmp/m1-91-compensated-w13-<revision>
```

The run root must not already exist. Do not run it while an API server is
active.

The fixed probe ran on physical GPU 0 of `ssh-73ca29ba` after per-card compute
and TP4 collective preflight passed. The attributable run used:

- source `6dbb8e1ba3e5f2e003f4d997b33174e88afa20f5`;
- immutable runtime tree
  `2ee781205fa722a323adcf1aa6b3d97ac22629a3a0c9aabf45b2d299e40b7f0a`;
- Torch `2.1.0+corex.3.2.3`, Transformers `4.55.3`, and vLLM
  `0.6.3+corex.3.2.3`;
- candidate extension SHA-256
  `e0698c7e4fc91cdef402374963796483c352f6e5e33e2842bc989f6615c2cc99`;
- production-direct extension SHA-256
  `0eb120e89608bb5b64ca4356a5d3d362121806d081ccc1ccf346dac472a819ec`.

An initial run at `52c4cfc` exposed a harness-only import defect: the direct
extension exports `PyInit_corex_moe_direct_routed`, while the benchmark asked
for `PyInit_corex_moe_direct_routed_compensated_gate`. Commit `6dbb8e1` fixes
only that import name and adds a regression test. It does not change either
kernel or the production runtime. The initial run produced no benchmark and
is not performance evidence.

The corrected run completed all 1,000 sequence steps and all timing trials:

| Seed | Fixed compensated/vendor L2 | Sequence compensated L2 | Max-step compensated L2 |
| --- | ---: | ---: | ---: |
| `20260716` | `7.30235e-6` | `1.44513e-5` | `5.40380e-5` |
| `20260727` | `5.94781e-6` | `1.42162e-5` | `6.54715e-5` |

The compensated kernel reached `6.0938x` fixed-shape and `5.4637x` routed
speedup over the vendor control. Its fixed fixtures passed `1e-5`, but both
sequence aggregates and both maximum-step values failed the numerical hard
gate. The production-direct sequence values also failed, at approximately
`1.45e-5` to `1.49e-5`; compensation reduced aggregate mismatch but did not
make the path acceptable.

Build, benchmark execution, runtime identity, source stability, before/after
GPU preflight, process-group cleanup, postflight, fatal scan, and timeout scan
all passed. No TERM or KILL recovery was needed, no process remained, and GPU
memory returned to its initial fully free value.

Privacy-safe evidence is retained in
`docs/experiments/evidence/M1_91_COMPENSATED_W13_BI100_REJECTED_20260728`.
Raw tensors and model data are not retained.

## Decision

`REJECTED`

The candidate fails the project-wide custom-kernel numerical gate despite
large microbenchmark speedup. Per the predefined stop rule, do not scan more
compensation variants, tiles, thresholds, or relaxed tolerances. This result
does not change the production kernel, model behavior, formal YAML, or any
default, and it provides no TP4, end-to-end, semantic-quality, or official
score claim.
