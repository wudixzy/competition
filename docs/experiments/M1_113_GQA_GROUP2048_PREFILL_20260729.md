# M1-113 GQA group2048 paged prefill

Date: 2026-07-29

Status: source and local static gates complete; BI100 compilation and
numerical/performance qualification pending M1-110 stage-profile evidence.

## Motivation

M1-109 keeps a bounded 2048-token workspace, but processes each group as four
512-token splits. Every group therefore launches four QK and four PV
`cublasSgemmStridedBatched` calls. Each batch contains the four query heads,
while all four heads share one K/V head.

M1-113 flattens the four query heads into the GEMM column dimension and treats
one 2048-token group as:

```text
QK: [2048, 256] x [256, 4Q]
PV: [256, 2048] x [2048, 4Q]
```

This reduces one group to one QK and one PV call. The candidate keeps FP16
inputs, explicit FP32 conversion and accumulation, FP32 online softmax/LSE,
head dimension 256, block size 16, GQA 4:1, query length at most 8192, and the
262144 context boundary. It does not change model weights, request semantics,
sampling, tokenizer behavior, YAML, or the default runtime extension.

The score workspace remains bounded by `4 * Q * 2048` FP32 elements and never
materializes full-sequence logits. Unsupported production shapes still use
the existing Python dispatch fallback because this file is only an
experimental extension.

## Selection gate

Do not consume a BI100 run solely because the source exists. Run M1-113 only
if the qualified M1-110 profile shows that QK, softmax, PV, and merge are a
material combined share and that gather is not the sole dominant bottleneck.

The fixed four-case component A/B compares the qualified M1-109 extension
against M1-113 on dense, 65K, 128K, and 235K production shapes. It requires:

- finite output and LSE;
- output and LSE relative L2 at most `1e-5`;
- output maximum absolute error at most `1e-3`;
- median M1-109/M1-113 speedup at least `1.10x`;
- at least three positive cases;
- no individual regression beyond 2%;
- clean scoped cleanup, fatal scan, postflight, and repeated four-GPU
  preflight.

The 2048-token online-softmax partition changes floating-point reduction
order relative to M1-109's four 512-token updates. If it misses the numerical
gate, the one permitted fallback design is a grouped QK with the original
512-token softmax/PV boundaries. If both reasonable designs fail numerical
or end-to-end gates, this route stops.
