# M1-159 order-preserving norm64 A/B

Date: 2026-07-30

Status: M1-159 preserved the M1-109 output and LSE exactly, but reduced the
fixed 16K, 32K, and 64K operator latency by only 1.1%-1.2%. It fails the
predeclared 1.08x component-speed gate and is not authorized for TP4,
long-context, quality, default, YAML, `main`, or official-score testing.

## Motivation

The M1-156 phase profile attributed roughly 19%-20% of the fixed P90-path
operator time to score normalization. M1-159 tests whether the normalization
kernel was primarily limited by launching 256 physical threads for a
reduction tree with only 256 logical lanes.

M1-159 changes only the normalization schedule:

- 64 physical BI warp threads simulate the original 256 logical lanes;
- each logical lane retains the same two-column local max and sum;
- the 128-to-64-to-1 reduction order remains unchanged;
- split order and FP32 online-state updates remain unchanged;
- QK, PV, paged KV gather, mask, merge, input, and output code are
  byte-identical to M1-109.

The candidate remains an isolated experimental extension and is absent from
the production patch overlay.

## Result

The fixed cells use query length 8,176 and total KV positions 16,368,
32,752, and 65,520. Baseline and candidate were interleaved for five trials
on identical inputs.

| Case | M1-109 | M1-159 | Speedup |
|---|---:|---:|---:|
| 16K | 72.085 ms | 71.303 ms | 1.011x |
| 32K | 135.958 ms | 134.429 ms | 1.011x |
| 64K | 263.908 ms | 260.698 ms | 1.012x |

The median speedup was 1.011x and the minimum was 1.011x. Every value was
finite. M1-159 and M1-109 outputs and LSE values were bit-identical in all
three cells. Candidate-versus-reference output relative L2 remained
`5.52e-6` to `6.19e-6`, and LSE relative L2 remained `1.52e-8` to
`1.80e-8`.

## Decision

The experiment isolates the normalization scheduling cost and shows that
physical-thread reduction is not a large enough lever for TTFT P90. The
candidate passes the numerical gate but fails the fixed component-speed
gate, so a model startup or TP4 service test would not be an efficient use
of the four-card window.

Do not continue scanning normalization thread counts or reduction layouts.
The next structural candidate should target the dominant QK/PV score-data
flow and avoid full score materialization while preserving the qualified
FP32 arithmetic. The 16K, 32K, and 64K cells remain the primary component
screen because the measured official-request distribution places TTFT P90
near the upper 16K-32K and lower 32K-64K buckets.

Scoped cleanup, postflight, repeated per-GPU preflight, memory comparison,
fatal scan, and source-identity checks all passed. Privacy-safe evidence is
under
`docs/experiments/evidence/M1_159_NORM64_AB_20260730`.
