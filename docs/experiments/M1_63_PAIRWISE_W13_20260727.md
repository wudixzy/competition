# M1-63: Pairwise W13 reduction gate

## Scope

M1-63 tested one bounded reformulation of the direct routed MoE W13 kernel.
The candidate uses pairwise accumulation to improve the direct kernel's
numerical behavior without changing weights, routing, dtype, or request
semantics. It was never enabled in the model or submission configuration.

The fixed gate required:

- relative L2 at most `1e-5` for two fixed seeds;
- relative L2 and maximum per-step relative L2 at most `1e-5` across 500
  independently routed steps;
- fixed-input speedup at least `1.5x`;
- routed speedup at least `1.25x`;
- finite outputs, clean pre/postflight, and no fatal device errors.

## Results

| Boundary | Reference median | Pairwise median | Speedup |
| --- | ---: | ---: | ---: |
| Fixed expert IDs | 0.134117 ms | 0.018107 ms | 7.407x |
| Routed expert IDs | 0.297280 ms | 0.060271 ms | 4.932x |

| Numerical case | Relative L2 | Limit | Result |
| --- | ---: | ---: | --- |
| Fixed seed 20260716 | 7.302e-6 | 1e-5 | pass |
| Fixed seed 20260727 | 2.974e-5 | 1e-5 | fail |
| 500-step aggregate | 1.401e-5 | 1e-5 | fail |
| Worst sequence step | 5.393e-5 | 1e-5 | fail |

All 500 candidate steps were finite. Only 7 of 500 were bit-exact with the
reference, so the aggregate result cannot be treated as a harmless isolated
rounding difference.

## Decision

`REJECT`.

Pairwise W13 substantially reduces kernel latency, but it does not satisfy the
quality contract across seeds or routed sequences. Do not integrate it, enable
it in YAML, or continue scanning reduction tiles. The direct and pairwise W13
route is closed unless a different algorithm can preserve the reference
reduction contract by construction.

The committed evidence contains only generated tensors' aggregate metrics,
runtime identities, and GPU health summaries. It contains no prompts, model
outputs, credentials, or model weights.
