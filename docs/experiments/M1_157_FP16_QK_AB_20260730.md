# M1-157 FP16-input QK A/B

Date: 2026-07-30

Status: the fixed three-GPU operator screen found a material 15.3%-17.2%
latency reduction, but all three cells failed the frozen operator
relative-L2 limit. M1-157 is not authorized for TP4, long-context, quality,
default, YAML, `main`, or official-score testing.

## Scope

M1-156 attributed 63.9%-70.1% of the existing fused-prefill operator time to
QK and PV. M1-157 changes only QK:

- query and key staging remain in the model's native FP16 representation;
- CoreX `cublasGemmStridedBatchedEx` receives FP16 Q/K;
- score output and accumulation remain FP32;
- the existing FP32 online softmax, FP32 PV, mask, merge, and final FP16
  output remain unchanged;
- the candidate is a private experimental extension and does not replace the
  production extension.

The fixed cases use query length 8,176 and total KV positions 16,368, 32,752,
and 65,520. Baseline and candidate were interleaved for five trials on the
same input and physical GPU.

## Performance

| Case | M1-109 | M1-157 | Speedup |
|---|---:|---:|---:|
| 16K | 72.087 ms | 62.540 ms | 1.153x |
| 32K | 135.993 ms | 116.767 ms | 1.165x |
| 64K | 263.888 ms | 225.094 ms | 1.172x |

The median speedup is 1.165x and the minimum is 1.153x. Trial spread is
small, so the narrower Q/K GEMM path is a real operator-level performance
signal. It is not an end-to-end TTFT claim.

## Numerics

Every output and LSE value was finite. Candidate-versus-reference max
absolute error was between `1.526e-5` and `6.104e-5`, and LSE relative L2 was
between `3.25e-8` and `3.66e-8`. However, output relative L2 was:

| Case | Candidate vs reference | Candidate vs M1-109 |
|---|---:|---:|
| 16K | 1.811e-5 | 1.818e-5 |
| 32K | 1.876e-5 | 1.874e-5 |
| 64K | 1.930e-5 | 1.930e-5 |

These values exceed the frozen `1e-5` Layer-3 limit. Small max-absolute and
LSE errors do not waive that failure, and task semantics cannot be used to
override it after observing the result.

## Decision

M1-157 is retained as evidence that QK input width has enough performance
leverage to matter for TTFT P90, but the tensor-op implementation is rejected
as a promotable candidate.

One pre-bounded numerical alternative is allowed: keep the same FP16-input,
FP32-accumulate contract and select CoreX `CUBLAS_GEMM_DEFAULT` instead of
`CUBLAS_GEMM_DEFAULT_TENSOR_OP`. It will run the identical three-cell A/B
matrix. It must restore relative L2 to at most `1e-5`, retain at least 1.08x
median speedup, and avoid any case below 0.98x. If it fails, close the
FP16-input QK direction rather than scanning algorithm IDs.

The runner completed scoped cleanup, postflight, repeated preflight, memory
comparison, fatal scan, and source-identity checks. Privacy-safe evidence is
under
`docs/experiments/evidence/M1_157_FP16_QK_AB_20260730`.
