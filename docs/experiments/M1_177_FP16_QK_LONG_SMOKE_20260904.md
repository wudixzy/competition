# M1-177 FP16-QK focused long-context smoke

## Decision

M1-162 remains a high-value candidate and may proceed to focused
teacher-forced distribution testing. A deliberately small TP4 smoke used one
131K and one 235K cold request per arm. The candidate reduced TTFT by 34.52%
and 53.38%, respectively, while every request reported zero cached tokens and
the first-token and complete-output digests matched control.

This is positive diagnostic evidence, not a formal performance qualification.
One repetition per length cannot support a confidence interval or a stable
tail estimate. The qualifier now reports
`positive_diagnostic_underpowered/inconclusive`, records no bootstrap CI and
does not authorize promotion. More long repetitions were intentionally not
run: both long buckets have a large positive margin, so the next information
needed is distribution behavior rather than another expensive timing sample.

Safe structured evidence is
`docs/experiments/evidence/M1_177_FP16_QK_LONG_SMOKE_20260904/summary.json`.

## Review fixes

Review of the completed M1-176 work found two harness issues and one reporting
ambiguity:

- A single repetition was previously allowed to produce a bootstrap lower
  bound and formal `pass`. It is now always underpowered. A clear stable gain
  can authorize the next diagnostic stage, but not long-context qualification.
- Runtime introspection and API service processes inherited the caller's
  working directory. Running from the repository root allowed the source-tree
  `vllm/` package to shadow the installed runtime overlay. Both now run from an
  isolated `runtime-workdir`; the failed setup probe is excluded from results.
- The control disables the complete fused-prefill selector. Results compare
  fused-off production baseline with the combined M1-162 path, not incremental
  M1-109-to-M1-162 service performance.

The v2 focused service also retains `cached_tokens`, first-token digest and
complete-output digest. Digests are behavior diagnostics rather than an
independent quality or numerical gate.

## Results

| Prompt | Control TTFT | Candidate TTFT | Paired gain |
| ---: | ---: | ---: | ---: |
| 131072 | 254.744 s | 189.376 s | 34.52% |
| 235000 | 587.346 s | 382.929 s | 53.38% |

The unweighted mean paired gain is 43.95%. No CI is reported. All four
requests completed with HTTP 200, complete SSE, eight completion tokens and
`finish_reason=length`. All four reported `cached_tokens=0`. Control/candidate
first-token digests matched 2/2 and full-output digests matched 2/2. Dispatch
counts were control 0 and candidate 4.

Both services used scoped TERM-first cleanup and were reaped. Postflight found
all four cards fully free and no API server, worker or GPU process. Fatal scans
found no OOM, non-finite value, segfault, collective reset, timeout or worker
loss.
