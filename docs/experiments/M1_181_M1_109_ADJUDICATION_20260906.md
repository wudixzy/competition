# M1-181 M1-109 lean adjudication

## Decision

M1-109 passed the requested four-rank real-activation G2 operator screen at
the representative 65K and 131K shapes.  It remains the primary
fused-prefill development candidate, with M1-108 as the conservative fallback.

The paired IFEval capability layer is `invalid`, not fail and not pass.  Two
TP4 attempts exposed two different harness defects.  The one permitted full
retry completed all 64 fused-off HTTP model requests, but the result was not
persisted before the following teacher-forced probe rejected the new `m1_181`
workload identity.  M1-109 and fused-off control B were never started, so
there are no paired IFEval counts, bootstrap bound, McNemar diagnostic or
calibrated fused-off-to-M1-109 distribution result.

Per the retry limit, no further model was started.  M1-109 is retained but
promotion remains blocked pending one reviewer-authorized paired IFEval run.
M1-162 remains parked: its G2 result and historical performance evidence are
unchanged, but its calibrated distribution drift and small direct incremental
TTFT gain do not justify further expensive capability work in this round.

The repository-safe machine summary is
`docs/experiments/evidence/M1_181_M1_109_ADJUDICATION_20260906/summary.json`.
No raw prompt, response, token identity, tensor, HMAC key or credential is in
the repository.

Historical M1-180 evidence JSON remains unchanged.  Its corrected meaning is:

- the 60 self-built cases establish only basic deterministic functional
  contracts, not statistical task capability;
- the reasoning prompt disclosed its answer, most strata were exact
  contracts, and long context stopped at 16K;
- fused-off to M1-109 and fused-off to M1-162 are uncalibrated distribution

normalized whole-term matching, so `red` cannot match `predominant`.

## Operator numerics

M1-136 alone was insufficient: its historical 65K observations did not prove
four-rank attribution and it had no 131K population.  M1-176 proved the four
rank mapping and supplied the reusable activation bank, but treated M1-109 as
the production baseline and therefore could not reconstruct the v2 error
ratios against a rounded-FP32 baseline.  The bounded replay was consequently
necessary.

Four GPUs replayed one logical TP rank each in parallel.  Each rank used the
same captured activation for context/query pairs `57344+8176` and
`122880+8176`, producing total attention lengths 65,520 and 131,056.  The
candidate was the existing M1-109 FP32-QK extension; the reference was FP32
and the production calibration baseline was the FP32 result rounded to FP16.

All eight cells passed.  Candidate-versus-rounded relative-L2 and max-abs are
retained only as diagnostics; the old universal fixed max-abs 0.001 rule was
not used to reject M1-109.  This is a rank-local real-activation operator G2
screen, not a new full-model TP4 claim.

## IFEval capability attempt

The frozen dataset was
`quality/external/google_ifeval/subset.v1.jsonl`, with its existing official
evaluator and original 8192-token completion budget.  No dataset was
downloaded.  The intended comparison was fused-off 64 cases followed by the
predeclared M1-109 16-case smoke and, only if safe, the remaining 48 cases on
the same service.

No valid paired capability result was produced:

1. At source `1166cfeb559338bc7926c27c2f768592daec7433`, fused-off
   completed two HTTP 200 requests.  The second exhausted 8192 tokens while
   still in `reasoning_content` and had no final content.  The harness
   incorrectly classified that scoreable IFEval failure as invalid.  It was
   fixed so only a genuine length-limited reasoning-only response is scored as
   empty output; all remaining HTTP/usage/tool/finish checks stay strict.
2. A launch at source `3ea4df28dd4bf8e2bdbc45e45ce775d3cf9a569d`
   omitted the already verified runtime-overlay environment from the detached
   shell.  It failed before API server creation or GPU work and is not counted
   as a model service startup.
3. The one permitted full retry at source
   `3ea4df28dd4bf8e2bdbc45e45ce775d3cf9a569d` completed 64 fused-off
   chat requests with HTTP 200, then failed before the first teacher-forced
   request because `teacher_forced_topk_api.py` accepted `teacher_forced` and
   `m1_180` manifests but not `m1_181`.  The IFEval result existed only in the
   workload process and had been removed with its private raw checkpoint, so
   the 64 generations cannot be promoted into statistical evidence.

The last defect is fixed.  The loader now accepts the `m1_181` attention-only
manifest, and the workload writes a privacy-safe IFEval result checkpoint
before entering any optional teacher-forced phase.  This prevents a later
focused-probe failure from discarding a completed capability population.
There was no second full retry.

Consequently strict/loose both-pass, baseline-only, candidate-only and
both-fail counts, the paired bootstrap lower bound and exact McNemar result are
all **not available**.  Statistical capability status is `invalid_evidence`;
it is not a model capability failure.
